## Transfer 1 — mechanical ports plus a separate holding-load ledger

Map the ideal assist to a generalized-force port `(b,qdot)`. Its instantaneous mechanical power is `bᵀqdot`; an energy/passivity analysis would combine this with storage, actuator power, passive forces, and disturbances. This can reveal omitted energy sources, but energy is not an instantaneous torque bound. The unexpected useful failure is a static task: zero velocity makes the power pairing blind to arbitrarily large holding force.

Exact CSV negative control: both assisted hold files have every recorded velocity and position-actuator force exactly zero, and each bias component is constant as a decimal rational. Peak bias is25.999662697619904Nm; mechanical bias work is0. The constant squared-bias integral over2s is approximately2083.407015Nm²s. The script also emits its exact decimal-rational value. An energy-only acceptance rule would miss this static load. Torque-squared duty is merely a load proxy here: no motor constants, resistance, current, temperature model, electrical energy, or permissible duty threshold are known.

Replay of all16 traces computes signed bias work, absolute net power integral, jointwise absolute work, torque-squared duty, and their sampled peaks. For fine-step assisted queued reversal, signed bias work is−2.1812232e−6J, absolute-net integral6.2220769e−5J, and jointwise-absolute integral1.2528512e−4J, despite peak tracking error9.212598mm. Signed work alone additionally hides cancellation; the two absolute integrals distinguish cross-joint cancellation. These trapezoidal integrals use the saved1ms grid, including files whose integration step was0.5ms. They are diagnostics, not continuous-time enclosures or a mechanical energy balance.

Preserved object: generalized force paired with the corresponding generalized velocity. Break condition: actuator scalar outputs cannot generally be added directly to joint forces; the transmission map must be bound first. The primary [MuJoCo computation documentation](https://github.com/google-deepmind/mujoco/blob/main/doc/computation/index.rst) distinguishes actuator outputs from their moment-arm mapping into generalized force, and identifies qfrc_applied as the user-applied generalized force. This script therefore uses only the logged bias copied from qfrc_applied and does not independently infer total actuator torque from column names. PM/domain audit that mapping separately.

Candidate contract: require BOTH a jointwise total-actuation bound on `B(q) f_actuator+b+other_commanded_forces` AND any claimed energy/duty bound, with the same clock, transmission, and force channels. Include torque rate only if its bound and evaluation semantics are supplied. Limiting the combined torque changes the assisted closed-loop equations whenever that limit activates; a corrected clamp requires a new tracking analysis. No claim is made that these recorded traces exceed a hardware torque rating.

## Transfer 2 — small-gain composition instead of seven isolated scalar claims

Map joint tracking errors to a vector comparison system. A possible sufficient certificate is a Metzler comparison matrix A with a positive weight vector p satisfying `A p ≤ −alpha p`, together with bounded residual input channels. Then a weighted tube can account for cross-joint coupling. The actual robot needs a verified comparison or energy inequality over a stated state region, not a matrix fitted to a successful trace.

Exact small falsifier: the two isolated scalar dynamics `x'=-x`, `y'=-y` are stable; connecting them as `x'=-x+2y`, `y'=2x-y` yields eigenvalue+1 on(1,1). Stability of each unconnected scalar does not establish stability of the coupled system. A separate positive toy with A=[[-1,1/4],[1/2,−1]] satisfies `A(1,1)=(-3/4,−1/2)≤−(1/2)(1,1)`, an exact rational weighted-row certificate. Neither toy is an identified FR3 model.

Recorded discriminator: in the stock hold fine trace, final joint1 command error is only2.25723e−10rad, while joints2–7 have displacement norm0.008031346rad and flange error6.053100mm. Peak joint1 error over the entire hold is only7.70239e−7rad. Therefore a contract watching only the deliberately commanded joint cannot explain the task-space error. In assisted queued reversal at peak flange error, joint1 error is0.016594713rad and off-axis displacement norm1.94397e−5rad: the dominant observed mechanism differs between these two cases. These norms diagnose missing channels; they are not a causal decomposition of Cartesian error.

Preserved invariant: an explicitly bounded coupled error set and a bound on the task map over that set. Breaks: treating radian error as meter error; replacing a full-region Jacobian/remainder bound by a point Jacobian; ignoring uncommanded joints, inertia coupling, friction, payload, orientation, or unknown physical controller. A task-space tube needs a certified kinematic map or enclosure as well as the tracking certificate. Source attachment-site position excludes orientation, tool, and gripper.

Map continuous reference construction to a signal-interface contract. The emitted1kHz position command is a zero-order hold, with jumps. Its classical derivatives are not the analytic four-box reference derivatives. Rather than importing a false jerk statement, bound the value difference between the smooth reference and the held input and feed that allowance into the coupled tracking proof.

Exact derivation for the original queued history: h=1/5s, +1/25rad event at11/50s, −3/50rad event at67/100s. The nonnegative four-box velocity kernel has maximum2/(3h). With command period1/1000s, the ideal smooth-reference versus exact zero-order-hold mismatch is at most1/5000rad. This is a value-error allowance; it does not make the held command smooth.
