Count a capability once: one user task, input/output contract, supported target and evidence. Link all supporting proofs, implementations and fixtures to it. A second language adds coverage; a second independent reproduction adds confidence. Neither automatically creates a second invention.

Trace the route to a consumer

Research question → precise model/property → proof or certificate → checked implementation → library adapter → end-user benchmark. Each arrow is an obligation to verify. An evidence manifest can track versions, licenses, units, numeric behavior and test results; it cannot make an unchecked arrow true.

Read the API and prior-art comparison. Start as an external example or wrapper. Propose an upstream change only when it fixes a demonstrated gap, preserves the host project's contracts, and fits its maintainers' goals. “Most performant” depends on workload, hardware, accuracy and constraints; compare the strongest relevant configuration.
