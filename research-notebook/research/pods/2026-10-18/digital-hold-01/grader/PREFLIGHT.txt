DIGITAL HOLD — PROGRESS REVIEW PREFLIGHT
18 October 2026. Prepared before builder freeze. No final proof verdict.

Decision to test
If the fixed 1 ms result passes, it changes one design decision: an engineer
can admit this holding mode when the declared state, sensor, actuator and
whole-age conditions hold. Whole age means reading timestamp to the current
physical time, including the time while a command is held. A nominal 1 kHz
loop alone does not meet this condition.

This is a useful model-level implementation bridge. It is not yet evidence
that a measured axis can meet the contract, or that the maneuver can brake
and enter this mode. No novelty or publication verdict follows from it.

Accept / repair / redirect / stop
ACCEPT the bounded sampled-hold milestone only if all A1-A6 pass:
A1. The frozen public statement preserves the declared cube at every time,
    on each arbitrary finite horizon, for the fixed gains and parameter
    bounds. It must cover a repeatable execution, not one isolated interval
    with an unproved recurrence premise. A smaller lemma is labelled partial.
A2. The execution specifies measurement and dispatch times, causal reads,
    measurement error, the first applied command and any initial history.
    It holds the measured command between updates and carries one physical
    state through updates. The age bound holds throughout each hold interval.
    A past sample needs a justified past history; initial cube membership
    at time zero does not certify an arbitrary state before time zero.
A3. Cube membership and aggregate mismatch are derived. Neither is a hidden
    global safety premise, nor a caller-supplied bound with the same missing
    bootstrap. Local hypotheses inside a proved first-exit argument are fine.
A4. Derivative jumps and update endpoints fit the trajectory definition.
    Rate/error regularity, finite switching, and existence scope are explicit.
    Conditional-on-existence safety can pass this bounded milestone when
    labelled as such. It cannot pass the executable-controller gate. An
    equilibrium witness alone does not prove existence for all initial states.
A5. Saturation location and target-error location are explicit. Either the
    actuator model includes clipping, or a derived command bound proves it
    inactive for this execution. Real arithmetic and implementation rounding
    remain distinct unless the finite-arithmetic bridge is checked.
A6. The independent critic accepts the actual frozen statement and replays
    its final source. Build, axiom and available separate-kernel evidence bind
    to source hashes. Negative controls challenge the contract. No forbidden
    proof escape, toolchain change or stale evidence supports acceptance.

ACCEPT an obstruction packet as useful progress, but not as a completed hold
milestone, if it identifies the exact false/missing premise or failing bound,
ties it to the attempted statement and evidence, and states what would repair
it. A failed sufficient bound is not evidence of unsafe plant motion.

REPAIR once if the critic identifies one local, bounded defect that can be

Examples: a slope constant, a missing endpoint case, or source/evidence drift.
Freeze again and replay affected evidence. No acceptance from promised edits.

What still blocks a complete stop-and-hold operation
1. A declared initial uncertainty set, pending command, two travel limits,
   available braking authority, and safe path during request/command delays.
2. Braking with the same changing response and error channels. A sampled
   detector must reach an admitted capture by a finite deadline. An assumed
   lucky reading does not prove eventual capture or safe rearward travel.
3. A state-preserving bridge into this digital hold, including its first
   sample/history contract. The older one-off 5 ms capture delay is not an
   ongoing 5 ms age permission, nor automatically a valid initial history.
4. Required terminal speed, acceleration, position width and settling time.
   Position containment alone does not meet an unspecified stop requirement.
5. A decision function tied to real timestamps, units, state ordering,
   sensor estimates and command placement; finite-arithmetic and measured
   response/error/authority evidence for any hardware claim.
