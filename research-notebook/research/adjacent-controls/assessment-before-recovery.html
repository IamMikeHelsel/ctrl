Apply u=−1 for T=1.25, then hand off to the existing sampled controller.
  • Outside the old region: every initial state in the box has energy at least 23.498378, above the old threshold 12.
  • Whole backup path: conservative position bounds are[0.82125,1.6553125], strictly inside the travel limits[−2,2].
  • Terminal recovery: exact interval arithmetic bounds terminal energy below 11.235, leaving margin below 12.

These checks cover all rates in the interval using 80 rational subintervals and all initial states using the affine flow and convex quadratic energy over 8 box vertices. The arithmetic uses exact fractions and Taylor bounds for the exponential. It is not a Lean proof: the checker, analytic enclosure, vertex argument and switching composition still need formalization. An independent agent review found no blocker in those arguments.

The backup lasts longer than the existing maximum feedback hold; its path is checked separately. The terminal state need not be at rest. The intended handoff checks the full position/velocity/acceleration state and then starts the original controller’s sampling clock. No acceleration reset or instantaneous stop is assumed.

Illustratively, τ₀=0.1 s and U=2 m/s² give an initial position around 2 cm, velocity around 0.1 m/s, a 125 ms backup and travel limits of ±4 cm. These are scaling examples, not measured hardware parameters.

Why a braking model needs more than velocity

For x₀=0 and v₀=a₀=U=τ=1, immediate maximum braking gives x(1)=1/2+2/e>1/2. The familiar instantaneous-acceleration guard v₀²/(2U)=1/2 is insufficient for this lagged actuator. This is a model mismatch, not a refutation of the double-integrator formula. The numerical stopping-distance diagnostic is about 2.6051; that decimal is not an interval-certified bound.

Delay adds another issue: a fast actuator can worsen forward acceleration while a command is pending, whereas a slow actuator worsens subsequent braking. A constant unknown lag must retain the correlation between those phases. Zero velocity also leaves residual acceleration, so one-sided stopping clearance is not by itself a two-sided, all-time safety controller.

Prior work constrains the contribution claim

Backup-set methods already turn backup flows and terminal sets into safety mechanisms. Robust backup methods already address uncertainty. Our potential contribution is a complete checked instance with a useful admitted region, explicit implementation assumptions and a reproducible comparison—not the invention of backup control.
