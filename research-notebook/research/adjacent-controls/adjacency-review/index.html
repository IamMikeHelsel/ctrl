What can we guarantee about an imperfect machine?

We need justified bounds on the real response. Then we can ask which actions stay safe throughout those bounds.

The shared question: Which physical explanations still fit the evidence, and which decision is justified across them?

This connects the brake example to your on-car balancing experience. Braking asks how far the machine could travel. Balancing asks which part causes the measured vibration, and where a correction would help. Both depend on what the measurements let us rule out. They need different physical models and different proofs.

1. MeasureRecord motion, commands, timing and operating conditions. Include sensor error.
2. Bound the possibilitiesKeep all physical explanations allowed by the chosen model and evidence. Preserve shared causes and dependencies.
3. Justify an actionCheck the decision against every retained possibility. If the evidence is too weak, use a conservative action or obtain better evidence.

Lean checks the logical claim. If the real system satisfies the assumptions, the proved conclusion follows. Measurements help assess those assumptions. A finite test record alone cannot establish that every future run will satisfy them.

The wheel example is about attribution

Your clarification was that the system had to distinguish wheel/tire imbalance from other drivetrain contributions. That is a source-identification problem: several causes may fit the same observations. More readings do not necessarily remove the ambiguity if those readings respond to the same combined cause.

At one frequency, imagine that two unknown contributions add to the measured signal. Several pairs can produce the same result. A correction that reduces one sensor reading may cancel the combined vibration at that location without establishing which part was imbalanced. Its effect at other speeds or locations needs checking.

A useful next exercise is to construct two different wheel/drivetrain explanations that produce the same available readings, then test what extra experiment separates them. A speed change, a known trial mass, or a different measurement location may help. None guarantees separation on its own. A trial mass can reveal the response to a wheel correction while leaving the original source attribution ambiguous.

There is a close public match: Braun et al., Driveline Imbalance Sensitivity Testing Methodology (SAE, 2005). Its abstract describes overlapping drivetrain rotation frequencies and wheel harmonics. It proposes slightly different dynamometer roll speeds at different wheels to separate contributions. This supports the relevance of your problem. The full paper was not available in this review, so its performance and applicability to your robot remain unassessed.

This is a proposed diagnostic exercise, not a diagnosis of your old system. The equations, sensors and mechanical arrangement are not available here. Focused source review and proposed test.

The next controls result should answer a design question

Recommended question: How much clearance does a controlled axis need when both its response speed and its available deceleration can vary during the maneuver?

Our current model allows an uncertain response speed that stays fixed through each complete run. It can cover different units or repeated runs if each run meets that model. It does not yet cover general changes during a run. More importantly, changing response speed does not model weaker braking. These need separate bounds.

The proposed extension bounds the complete position, velocity and acceleration response while both response speed and effective acceleration target vary within stated limits. It can reuse our exact-flow and interval work. It still needs a new comparison proof, useful numerical margins, and evidence that the chosen axis fits the model. See the precise candidate theorem and counterexample.

Choose the mechanism first. Our negative motor command models powered deceleration. A friction brake can have engagement delay, direction-dependent torque and a separate holding mode. Official robot guidance already recognizes temperature, wear and contamination effects. A larger lag interval does not automatically cover them. DGUV industrial robot guidance, pp. 24–26.

Where PL d and PL e fit

A transient proof could support a requirement such as “after a stop request, travel stays below this limit and the axis reaches the specified stopped condition by this deadline.” Our present theorem proves bounded travel and continued bounded motion. It does not yet prove that stopped condition or a maintained stop.

Performance Level also depends on dangerous failures, component reliability, architecture, diagnostics, common causes, software and validation. Formal verification can support the behavior and design argument; it does not supply all of that evidence. The ISO 13849-1:2023 scope and IFA Report 1/2025 support this distinction. The independent review records the details and access limits.

A bounded next experiment

  1. Use one decision. Start with allowed approach speed or required clearance for a controlled axis. If we target a stopping safety function, also specify its deadline and stopped/holding condition.
  2. Challenge the model before expanding the proof. Vary response speed, braking strength and delay separately. Include a case that the old model accepts but the richer model rejects.
  3. Compare the same assumptions. Use a simple conservative engineering bound and an established reachability method. Measure useful clearance, accepted states, checking cost and manual setup effort.
  4. Add evidence across conditions. For a physical claim, keep units and complete runs separate between fitting and challenge data. Include load, cold start and repeated operation. A good average fit is insufficient.
  5. Advance only with a useful difference. Continue toward a paper if the checked result changes a real decision, closes a relevant unchecked step, or makes an existing workflow materially easier. Otherwise retain it as a reusable educational/reproduction artifact.

The wheel/drivetrain example is a second, bounded investigation into what measurements can distinguish. It should enter the same paper only if a shared method produces useful results in both cases. Shared motivation alone is not enough.

What is proved now, and what remains open

The original recovery proof covers its selected initial box and fixed lag range. The newer direct-feedback pilot now has between-sample safety, a finite-prefix handoff and all-time travel safety for one initial subbox and one rate cell. The full direct-feedback covering remains open.

The latest interval-checker replay passed: 12 new modules, 64 new named theorem declarations, plus the existing two-declaration TerminalBase dependency. The audit checked standard axioms and separately replayed all 13 modules. The deliberately false terminal-energy claim failed as required. Pinned base/mathlib artifacts remain dependencies.

GeneralHandoff composes an explicitly supplied safe prefix and terminal-state condition with the existing controller. Its generic prefix is only assumed continuous; its physical dynamics are a separate caller obligation. The new variable-response proposal, hardware validity, online monitor, finite-word controller implementation and PL assessment are unproved.

Six examples that limit the performance claim

The numerical comparison includes rest, slow travel, the original nominal case, motion toward the target and faster approaches. Fixed braking worsens some cases; one selected case crosses the opposite travel limit. Both methods fail in sufficiently aggressive examples. These are numerical illustrations, not formal unsafe-state certificates.

The examples support a state-dependent decision about whether to brake. They do not support a claim that a fixed brake is generally better than direct feedback. See the six trajectories · Method and limits.
