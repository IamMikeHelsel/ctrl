Working public title
Treating the Tremors We Built into Robots
Subtitle: What a checked execution layer can promise
The title is an engineering metaphor. It does not claim a neurological cause.

Paper type
A formal-methods engineering case study with reusable checked reference
contracts. A new smoothing algorithm or a general solution to VLA jitter is
not established. No hardware is available in this round.

One argument
A smooth plan, an accepted request, and a completed physical task are different
objects. A finite execution history permits exact checks of declared future
reference limits. A separate physical model gives conditional tracking and
settling bounds. Deadline failures, travel, and implementation costs must remain
visible when judging whether the executor is useful.

Proposed short structure
1. Task goal, reference, physical state. Show the three distinct errors and one
   known overlapping-reversal failure. Credit Biagiotti/Melchiorri2012 §4.1.
2. Four-box reference and finite-history contract. Exact rational jerk check;
   exact acceleration check with interior critical points. Define current and
   future roots, signed cancellation, and positive-width conditions.
3. Admission and execution. Preserve committed actions and the executed prefix.
   Finite candidate search has limited completeness. Rejection is a service
   failure. Add pruning and successor equivalence only after accepted review.
4. Conditional scalar plant result. State response, disturbance, initial-state,
   trajectory-existence and continuous-time assumptions. Position arrival is
   not exact rest. Keep the terminal settling result separate unless composed
   with this same reference and inherited state.
5. Common-prefix comparison. Same actual revision state; native fast and native
   matched reference arrival. Report all task failures, squared-jerk integral,
   extra excursion, tracking and settling together. No post-result tuning.
6. Artifact, trusted boundary, source comparison, and hardware questions.

Evidence selection
Use the common-prefix gate as the main figure only after its independent review.
Keep the earlier differing-state comparison as a negative audit in the supplement.
Keep the original failed acceleration example. Use the old favorable periodic
hold example only to explain the frequency-zero confound, not as main evidence
for improvement. The 2012 source already discusses the reversal failure.

Essential comparison caveat
A native minimum-duration constraint is not an optimizer of squared jerk.
Matching reference arrival removes one confound, not every tradeoff. Additional
forward travel after reversal can matter more than smoothness. Report metrics
as separate axes; no single unsupported score or winner.

Velocity and physical stopping gate
The general candidate selector currently lacks a generic velocity check.
Concrete return velocity is proved separately. A sufficient Bernstein cell
check could close that interface; it must not be called necessary or exact.
For arbitrary changing disturbance, the improved terminal-output scout is
numerical. A universal certificate needs both invariant bounds and entry by
its stated time. Constant bias has a narrower proved result. Do not mix them.

Portable artifact
Create a new final bundle, preserving the old certificate03 package. Include
byte-identical accepted sources, pin and source bindings, fresh closure replay,
axiom/kernel checks, false controls, theorem-to-claim map, and exact measured
benchmark inputs. Avoid absolute workspace dependencies in the portable runner.
A source archive that still depends on a provisioned pinned mathlib cache must
say so. Public license and release scope remain Mike's choices.

Open publication decision
Agent reviews check the evidence. A human controls/formal-methods specialist
must judge usefulness and novelty. If the result is routine mechanization,
a technical note and reproducible software artifact are honest outcomes.
Do not expand the claim merely because proofs and credit remain available.
