Expanded proof package — integration plan

Copy frozen sources byte-for-byte from accepted history-pruning, successor,
velocity, physical-arrival, new FIR hold and new future-commit gates. A new gate
must have a separate accepted critic before the final package is frozen.
The union permits duplicate module names only if their bytes match. Keep each
original gate manifest and closure, including copied inherited-source paths.

Pin the exact roots, kernel targets and full negative-control path/hash mapping
inside replay.py. A rewritten local input manifest must not permit removal or
replacement of any planned proof check. Keep the exact source and review gate
hashes in that script. Check pin files and actual mathlib revision.

Replay from an empty local build directory with public dependency caches only.
Audit every declaration in every local module and replay the named kernels.
Require exact negative controls to fail for mathematical reasons. Source changes,
missing checks, changed roots and changed controls must fail before compilation.
Keep old proof bundles and all failed package attempts.

The rational JSON client is a separate end-to-end gate. It emits a Lean decision
proof and reference contract for acceptance, or unchanged-state theorem for
rejection. It must not imply that a rejected task was completed. Its common-clock
and atomic-commit assumptions must be stated. This is a prototype, not robot code.

No replay or package result proves physical premises, coupled-arm safety,
real-time capacity, novelty, or publication readiness.
