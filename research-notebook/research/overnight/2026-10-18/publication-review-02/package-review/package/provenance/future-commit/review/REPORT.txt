What the theorem establishes
FutureCommit.successful_commit_contract concerns the actual Base returned by
commit, not an unrelated checked history. Full Base and Task equality bind the
certificate to the live events, offset, width, versions, goal, request, deadline
and limits. It checks the signed increment against the desired final goal and
the selected execution time against the finite candidate selector.

The clock test requires request <= completion <= atomic commit, nonnegative
dispatch allowance, and atomic commit + allowance <= execution. Success appends
the unchanged event. It gives all-future reference V/A/J bounds from request,
prefix equality through execution, and exact reference rest at the live task
goal from the absolute deadline onward. The speed test is sufficient and can
reject a safe trajectory. It is not an exact speed-extremum test.

The generic prefix theorem covers both accepted and rejected transitions.
Rejection returns the live Base. A successful transition changes its version
and history. An independent generic client proves that a second use of the
same pending result rejects for every second task and timing and retains the
first committed state. This is a reachable duplicate case.

Meaningful lost contracts
Removing time binding allows the 0.62 s event to be committed at 0.70 s. Its
reference position then differs from the already continuing old reference by
-8/375000 m. Removing history binding can send the reference to +1 mm, and a
reachable duplicate return sends it to -20 mm, instead of the requested zero.
Removing task binding reaches zero when the live task asks for +5 mm.

Two extra independent checks connect metadata errors to real reference failures.
Changing the checked execution from 0.62 to 0.52 s gives acceleration -21/32 m/s^2
at 0.77 s, beyond the 0.5 limit. Omitting the signed-increment/goal equality admits
a geometrically valid zero increment that still ends at the old +20 mm target.
These are reference-value failures, not only false Boolean decisions.

Wrapper defect, reproduced
The old client.py reads JSON before proof execution but hashes the input path
after execution. A controlled replacement after ClientProbe.lean was written
left a valid compiled and kernel-replayed proof of the zero-goal input, while
result.json recorded the hash of a different file whose live goal is 1/200 m.
See input-race/before.json, after.json, finding.json and output/ClientProof.lean.
The test used real Lean and kernel checker execution. No proof result was faked.
The old wrapper also accepts duplicate JSON keys under Python's last-value rule.

Repair: read once, retain those exact bytes in a fresh output directory, parse
that snapshot, and hash the saved snapshot. Reject duplicate keys or explicitly
specify and test their meaning. Root reports that a new adapter implements the
snapshot and duplicate-key repair. That replacement was not reviewed here and
requires its own acceptance. Preserve this frozen builder and the counterexample.
The defect does not invalidate the six unchanged-input results or Lean theorem.

Limits that must remain visible
Completion includes verification only by assumption. All timestamps refer to a
common ideal clock; the dispatch allowance must bound actual delivery. The
0.52-to-0.57 s interval is a declared scenario, not measured computation latency.
The abstract commit assumes one atomic live-state capture and update. Its pure
code includes certificate computation; it is not a verified asynchronous machine
implementation or a worst-case execution-time result.

Reference bounds are not physical actuator bounds. The theorem contains no
physical plant state, sampling, obstacle safety, emergency stop, hardware timing,
Franka dynamics or VLA performance claim. It covers one fixed retained history
returned by one transition. Later accepted updates can supersede the task. A
rejected request can leave the old goal active. There is no liveness theorem,
automatic retry or guarantee that this finite candidate list finds a useful plan.
Exact structural identity can reject an equivalent reordered or pruned history.
The natural-number versions do not prove machine-integer wraparound behavior.

Scope and stopping decision
The source claims state these boundaries candidly. Prior-art and publication
value remain separate assessments; this review does not certify novelty. Stop
new theorem growth at this gate. Finish and independently review the portable
snapshotting client, integrate the bounded result, and keep the physical-clock
and atomic-execution questions explicit. See NEXT-GATE.txt.
