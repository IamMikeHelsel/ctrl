Scope audit — final portable package

I read the actual FutureCommit, VelocityAdmission, VelocityGuard and FIRHold
statements. I also inspected the replay, rational parser, client wrapper and
source/review binding plans. The new package does not strengthen the reviewed
mathematical claims. It joins their original source bytes into one fresh build.

A successful commit proves all-future bounds for one retained reference from
request time, equality with the old reference through the chosen execution time,
and exact reference rest at the supplied task goal after its deadline. Full
base/task data equality is required. The clock inputs and atomic read/update are
premises. The result is not an implementation that measures those facts.
Rejection retains the old base. It need not satisfy the newly requested task.
The finite selector and sufficient speed test can reject feasible motions.
A later accepted update can supersede an earlier task. No liveness claim follows.

The physical theorem uses the fixed delayed return and a supplied classical
trajectory. The same trajectory, response and disturbance are shifted together.
One initial error cube is assumed. Position is confined to a 0.2 mm tube; after
the reference stops at 1.42 s it lies in the corresponding position band. The
speed and acceleration bands hold from 3.42 s, not the numerical task deadline
of 1.70 s. Exact physical rest does not follow. No existence theorem for all
bounded discontinuous inputs, coupled arm result or hardware validation is added.

The replay rebuilds each local module in a new .build directory. Its LEAN_PATH
puts that directory first, followed only by provisioned package caches. It
excludes the dependency project's own compiled products. It audits every local
declaration and separately runs the 22 fixed kernel targets. The 33 false-client
filenames and hashes are fixed in the code, as are source roots and complete
source/review binding hashes. Public library binaries are reused and trusted.

V2 had a dependency-file identity gap. Changing lakefile.toml in the package and
supplied dependency project, then rehashing the local input manifest, passed the
precheck. This did not alter any theorem. V3 fixes the three original file hashes
in replay.verify_inputs. The same mutation now fails. The old package and test
remain preserved; no shared dependency project was edited.

The client reads the requested input bytes once. It parses strict keys and exact
rational strings, saves the same bytes, emits exact Lean literals, proves the
computed decision and its appropriate consequence, audits both theorem axiom
lists, and separately kernel-checks the generated module. Parsing itself is not
formalized. The prototype's limit and timeouts are resource bounds, not real-time
capacity. The timestamps are declarations, not measurements of this process.

The package and completed replay record are trusted local evidence. Hashes are
not signatures. A person who can change the checked scripts and their recorded
hashes, forge the replay record, replace the library/compiler, or alter outputs
can subvert provenance. This package makes no adversarial remote-attestation
claim. Tests of ordinary changed source/object files must reject; tests that
forge all trusted metadata are outside that stated boundary.

The velocity review provenance intentionally retains an earlier result.json
failure and its later final-result.json acceptance. Its report and scope review
explain the repaired review evidence. The original failed file is not a current
acceptance claim.
