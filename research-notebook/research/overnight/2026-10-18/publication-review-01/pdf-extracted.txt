Treating the Tremors We Built into Robots
What a checked execution layer can promise
Mike Helsel
Working draft for technical review; AI assistance disclosed
18 October 2026
Abstract
A smooth reference, an accepted request, and a completed task are diﬀerent guarantees. We formalize
part of their connection for a scalar execution layer built from an established four-stage moving average. Lean
checks a rational ﬁnite history against jerk and acceleration limits at every future real time. A ﬁnite candidate
rule preserves committed motion and can delay or reject a new execution. We prove that completed event tails
can be removed without changing future motion, and that a checker using adjacent knot cells has the same
acceleration decisions. A separate, conditional theorem carries the physical state from time zero and proves
position tracking, progress, and position arrival for one return task.
A predeclared numerical comparison starts three methods from the same reference and physical state. The
retained ﬁlter has about 0.40 times the squared-jerk integral of a native planner with matched arrival, but
about 2.09 times its extra forward travel. Only the native fast method completes the tighter task. These
results support a checked-contract case study, not a new smoothing algorithm, a general VLA remedy, or a
physical robot result.

The case study asks whether a ﬁnite retained history can make these contracts explicit and executable. It does
not infer whether a new request is noise or a real change of intent. The title describes an engineering symptom;
it does not propose a neurological mechanism.
Prior work sets the scope. FIR planning and derivative limits are established. Biagiotti and Melchiorri
already discuss acceleration growth under an overlapping reversal and waiting as a response [ 1]. Their later work
addresses time optimization under kinematic and frequency constraints [ 2]. We use the reversal as a regression
case, not a discovery. Ruckig supplies online jerk-limited motion from nonzero initial states [ 3]. Reference
governors and ModelPlex already connect future constraints, uncertainty, and checked execution [ 4, 5]. The
proposed contribution is the specialized Lean contract and its reproducible boundaries. Its research value still
needs external specialist review.

For rational inputs, the Lean Boolean checks have these all-future real contracts. Invalid widths and negative
limits are rejected.
Proof structure. An aﬃne function has its absolute maximum at a cell endpoint. A quadratic function can also
attain its maximum magnitude where its derivative vanishes. The formal argument constructs cells from the event
list, including the current time and the ﬁnal tail. Repeated, unsorted, expired, and queued events are covered. It
does not rely on a sampled graph.
The ﬁrst acceleration implementation enumerates candidate pairs. A proved replacement takes the minimum
strictly greater knot for each left endpoint. The theorem same_acceptance equates the two Boolean results,
including invalid-input rejection. This optimization changes evaluation work, not the accepted set.
Theorem 2 (Removal of completed tails). Remove every event with τi+4h ≤ c, and add the sum of its increments
to g0. For every t ≥ c, the resulting position, velocity, acceleration, and jerk equal those of the original reference.
Both guard decisions are preserved.
Completed responses have position contribution δi and zero derivative. This result does not preserve past motion
or bound the number of active events. An unbounded arrival rate can still require unbounded active history.
3 Admission can repair a limit and still fail a task
A new increment is relative to the ﬁnal committed target. An append-only admission rule retains earlier events.
Execution cannot precede admission. The separately proved causal wrapper also orders execution times. Rejection
retains the existing reference. A new event contributes zero through its execution time, so the executed position
and its ﬁrst three derivatives remain unchanged.
For a ﬁnite supplied list of candidate execution times, the timed selector checks τ ≥ c, jerk, acceleration, and
completion of every event by a reference deadline D. A selected candidate therefore preserves the preﬁx, meets
those reference bounds, and reaches the ﬁnal committed target at rest by D. A result of none says only that the
supplied candidates failed. The selector is not a complete trajectory planner. Its current general interface has no
velocity guard; the concrete return below has a separate velocity bound.
Fixed reversal. Use h = .2 s. A +20 mm event starts at .22 s. A return to zero becomes available at .52 s. An
immediate −20 mm event passes the jerk limit 7.5 m/s3, but its acceleration reaches 21/32 = .65625 m/s2, above

results are outside this paper’s composed task theorem.

An independent replay used 80-digit arithmetic and a diﬀerent physical propagator. It checked all 271,884 state
rows and 1,356 event rows with no task-decision mismatch. Fresh native plans and 7,922 native queries matched
the saved exports. Both output grids give the same decisions. The largest position diﬀerence between propagators
was 4.2 × 10−16 m. This is agreement between numerical models, not a hardware error bar.
The FIR/native-matched squared-jerk ratio is .398–.402, while the forward-excursion ratio is 2.085–2.090. Native
fast alone passes the tight task. Matching arrival removes one confound; it does not match the paths or make the
native method a squared-jerk optimizer. A stronger performance claim would need a smooth baseline with the
same arrival and an explicit excursion limit. We do not infer general superiority from this comparison.
6 Proof artifact and practical limits
The portable package binds 50 local source modules to three frozen proof gates. Its replay builds local sources
into an empty directory, checks every local declaration for unsafe code and unapproved axioms, runs separate
kernel checks for nine main modules, and requires twelve false clients to fail for mathematical reasons. Public
dependency caches remain a declared trust boundary. The permitted axioms are propext, Classical.choice,
and Quot.sound. The package wrapper itself awaits independent review.

Exploratory shared-host timings put the new 32-event checker near 220 ms, versus about 22.5 s for the earlier
enumerating check on the same ﬁxed inputs. These are Lean –run measurements, not worst-case bounds or
production native timings. They do not establish a 1 kHz implementation. Removing completed tails helps
storage only when active event arrivals are also controlled.
The next practical test needs measured clocks, an execution schedule, a command interface, and a coupled robot
model. Franka is the intended later platform; no robot was used here. Contact, payload variation, joint coupling,
actuator saturation, and sampled actuation need their own assumptions and acceptance tests. The result does
not certify a machine-safety performance level.

Relation to learned and industrial execution. Real-Time Chunking and VLA-RAIL already retain or
combine actions across changing plans [ 6, 7]. The present scalar history is not a full action chunk. Industrial
systems also expose path and timing choices: F ANUC documents timing conﬁguration, while Yaskawa describes
its SMOOTH function [ 8, 9]. Those public interfaces motivate explicit execution contracts. They do not establish
the vendors’ internal algorithms or provide a measured baseline in this study.
