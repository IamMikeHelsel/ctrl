PROPOSED NEXT WORK: ONE COMMON DIGITAL STOP-AND-HOLD CONTRACT
18 October 2026. Planning decision from internal review; not a proved extension.

Paper direction
The main contribution should answer an engineering question about clearance,
response, measurement error and information age. Retain the fixed-rate sampled
result as infrastructure or a secondary benchmark. Do not append all the motion,
GU, vehicle, grip-loss and safety-certification work to one manuscript.

Next 45-60 minute milestone: digital hold feasibility
Keep the existing k=-8(x-c)-6v-a/2, rate range [8,12]/s, R=.055525 m,
sensor bounds (.001 m,.01 m/s,.05 m/s^2), target error .01 m/s^2, and
illustrative authority 2 m/s^2. Aim at total information age <=1 ms first.
The exact arithmetic screen has positive slack here. Do not raise it to 5 ms
or widen the tube simply to get a successful result.

Deliver one explicit sampled execution predicate and either:
  (a) a noncircular one-step/cube invariance proof with the declared budget; or
  (b) an exact obstruction showing which premise or bound prevents that proof.
Cover the first command and sample history. Specify timestamp order and total
age, not just nominal sample period. Carry physical state across updates.
Account for derivative jumps and prove or state the precise existence result.
Keep saturation semantics explicit; a command bound may prove it inactive.

Acceptance requires a later independent reviewer to inspect the statement,
actual implementation/model link, fresh-source Lean evidence and negative
controls. A builder cannot accept the milestone. No new reviewer was dispatched
by this self-assessment. This file does not claim the milestone is complete.

Failure rule
If the proposed bridge is circular, incompatible with the existing theorem's
trajectory class, or too conservative at 1 ms, record that exact obstruction.
Allow one justified alternative enclosure or direct sampled proof. Do not spend
an open-ended batch generating more similar lemmas. A failed sufficient test
does not establish a plant safety violation.

Then close the whole operation, before broadening the robot
1. Start from a declared full-state uncertainty set and a known pending command.
   State the lower/upper travel limits and sensing/command error channels.
2. Derive the path bound during request delay and braking with changing response.
   A guaranteed negative target requires a lower bound on available braking
   authority. Faster or slower response alone does not specify brake strength.
3. Define a sampled detector and prove that an admitted capture occurs by a
   finite deadline. Bound the entire path until the actual command switch.
   A conditional theorem starting from a lucky accepted reading is insufficient.
4. Use the same state, rate and disturbance functions at handoff. Prove ongoing
   digital holding. State residual velocity and acceleration bands if a stop is
   claimed. Position containment alone remains a separate result.
5. Bind a runnable decision function to these inputs and guarantees. Report its
   floating/fixed-point trust boundary until finite arithmetic is verified.

Comparative gate, defined before the new experiment
Choose one common model, actuator limits, initial region, timing, disturbances,
measurement bounds and acceptance property. Include a credible robust sampled
backup/safety method from the adjacent literature. Implement its stated
assumptions and document any adaptation; do not compare only with instantaneous
v^2/(2U), zero-command release, or an intentionally slow filter.

Use the old fixed-lag direct-controller result as context, not a matched baseline
for changing-response digital operation. The baseline must be rerun on the same
new contract. Give methods comparable tuning and compute budgets; report failed
attempts and certificate failures separately from unsafe trajectories.

Report the trade a user can act on:
- admitted initial speed/acceleration versus available clearance;
- allowable total information age versus sensing and target error;
- terminal position width, speed/acceleration bands and time to reach them;
- certificate conservatism against a declared validated reference calculation;
- model-specific manual proof work, certificate size and checking cost.
Do not average away worst-case safety failures. Do not call numerical simulation
the ground-truth viability boundary. A checked limit is not necessarily optimal.

Value gate
Proceed toward a paper if one comparison demonstrates a meaningful benefit, or
if an independent consumer on a different plant demonstrates useful reuse of
the checked interface. A formal-methods paper can contribute reproducibility,
composition or reduced trusted computation without a faster controller, but
that value still needs evidence and an overlap audit.

Stop or redirect if the complete operation has impractical bounds, duplicates
an existing checked interface without added value, or cannot meet a declared
task. Preserve the result as a library/tutorial artifact. More examples alone
do not change this decision.

Questions needed before a real application claim
Which mechanism and command interface? Which travel and terminal-motion limits?
How is acceleration estimated? Which measured response/authority/error bounds
hold under load and temperature? What worst-case information age is measured?
These inputs can wait. The current parameter study must remain illustrative.

Suggested future paper outline, conditional on passing the gates
Task and timing problem -> common model and assumptions -> complete operation
theorem -> checked decision interface -> matched comparison and negative cases
-> reuse/trust boundary -> measured limitations and open implementation work.
Each theorem should support that one operation or its evaluation.
