Filter scope and nuanced states
-------------------------------
The default filter implements exactly the four included states above. It
excludes proved (336), disproved (139), solved (101), not provable (3),
not disprovable (6), and independent (3). Among official-listed prizes, the
last three nuanced categories exclude #474 (not provable) and #1123
(independent). These two entries are available through Show all.

The JSON gives the included state list explicitly, and the HTML footer says
the filter excludes other nuanced states and directs users to Show all.
This is sufficient for the current label 'Ordinary unresolved labels'. Never
shorten the result to '59 open prizes' or '59 remaining prize problems'.
Optional clarity improvement: name not provable, not disprovable, and
independent in the footer, rather than only saying 'other nuanced states'.

Prize and formalization semantics
--------------------------------
- Every manifest prize_payment_verified is null; every corresponding CSV cell
  is empty. All official-list payment_verified fields are also null.
- The HTML prominently labels rewards as historical/source claims and payout
  as unverified. Each official-listed table amount repeats 'unverified payout'.
- Original community currency strings are retained separately from the site's
  display amounts. For example, #710 and #711 have different rupee strings
  but the same $78 official display. The artifact does not invent or claim
  an exchange-rate reconciliation. Such discrepancies require source-specific
  investigation before relying on a particular amount.
- The stored site FAQ says publication in a reputable journal and documentary
  support for the historical amount are prerequisites to award consideration;
  the catalog makes no claim that checking a proof alone earns a prize.
- Schema comments distinguish formalized statements from formalized solutions.
  Manifest fields, table columns, filters, and the explicit statement-is-not-
  proof warning maintain this distinction. A Lean solution tag is copied
  community metadata, not a claim that this project built or semantically
  audited that solution.
- The title's 'full current' scope is immediately limited to the pinned
  community metadata catalog, explicitly not every question Erdos ever posed.
  The pinned revision and snapshot date are visible. Links to statements use
  the upstream moving main branch; they are browsing links, not immutable
  statement artifacts. The manifest does not claim statement completeness.

Minor future-maintenance issue, not a current-snapshot error
---------------------------------------------------------
The upstream schema only requires the number field, while this snapshot has
prize/status/formalization fields for every row. The manifest correctly uses
null for missing source fields. If future rows omit a prize field, the HTML
currently falls through to 'No listed reward'; it should instead display
'Unknown' when neither source establishes absence. No current row triggers
that branch with unknown community-prize data.
