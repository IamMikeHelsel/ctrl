PROPOSED CONTRIBUTION SENTENCE
We give a reproducible Lean case study that connects exact interval certificates
for a clipped actuator with fixed lag uncertainty and held errors to an explicit
sampled-feedback execution contract, existence/uniqueness and all-time travel
safety, with physical scaling and model-mutation checks.

WHY THAT COULD HAVE VALUE — STILL A HYPOTHESIS
The certificate is not left disconnected from the actual ODE. The same sampled
state determines the feedback in the execution definition. The initial full-state
set, clipping location, rate factor, clock coverage and physical units are all
visible. A user can inspect why an apparently valid matrix witness does not
validate a changed model. These are useful engineering/formalization concerns;
their publication value requires evidence of reuse or an independent assessment.

LEAN API CANDIDATES TO INSPECT
BernsteinCertificate: finite rational matrix positivity and interval coverage.
VertexCertificate: quadratic convexity that transfers vertex inequalities.
StepScaledRobustness: generic quadratic-form perturbation bounds with elapsed time.
ExecutionUniqueness: concrete held-ODE uniqueness and own-sampled-state execution.
PhysicalExecutionUniqueness: physical normalization and trajectory correspondence.
The first three are reuse candidates. The last two are substantially tied to the
declared actuator. Generality of a type signature is not evidence of actual reuse.

THREE FALSIFIABLE NEXT GATES — PICK ONE, NOT ALL
G1. Independent consumer (preferred Lean-value test).
    A reviewer applies the unchanged generic certificate/perturbation interface
    to a different declared plant, with its own model-binding proof and a false
    model mutation. Accept only if the proof avoids copying the application
    modules and documents which manual obligations remain. Rescaling the same
    axis or replaying existing benchmark matrix files does not pass this gate.
G2. Matched verification comparison (stronger pipeline claim).
    Freeze one common plant, controller, initial set, timing/error assumptions
    and target property. Reproduce it in a relevant existing system, recording
    preparation effort, proof trust boundary and completed checks. One pipeline
    failing to support a feature is not evidence that its mathematical method
    cannot do so. No existing run currently establishes superiority.
G3. Measured application (practical-value test).
    Choose an actual task and estimate its lag, sampling, error and initial-state
    bounds. Check whether the certified envelope is useful under those bounds.
    If time-varying response plus sampling/clipping is essential, state and prove
    that NEW model. Combining two separate theorem summaries does not pass.
