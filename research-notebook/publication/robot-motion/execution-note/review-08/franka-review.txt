FRANKA SMOKE REVIEW — 18 October 2026 UTC
Reviewer: controls_task_analyst. Bounded read-only source and saved-data review.
Decision: the revised description is supported as a simulation integration smoke
check. No blocking defect found within that limited scope. This is not independent
physics evidence, hardware acceptance, or a transfer of the scalar Lean theorem.

What was checked
I read the protocol, implementation, coordinator audit and results, README,
hardware plan, and final paper fragment. The requested audit.py is actually named
audit_smoke.py. I inspected the two FR3 XML files and verified all 128 current
model files against model-provenance.json. I parsed all 16 saved CSVs independently
with Python's standard library. No physics, audit script, or renderer was rerun.
No frozen input, proof, trace, or publication source was changed by this reviewer.

Causality and state retention
The executor admits a packet only when its arrival time has passed. The receive
check enforces issue<=arrival<=now<=execution and increasing epoch numbers. Its
reference uses only received events. An accepted future event contributes zero
before execution, including its first three derivative values at execution.
The delayed reversal arrives at .61 s and starts at .67 s; this retains the
previous reference prefix for 60 ms. Actual joint state is reset only once at
run start. The fixed packets reveal no use of a later goal before arrival.

The full packet list is available to the harness, but issue-time truth is used
only for scoring in separate goal_data. It does not enter command generation or
the physical state's force calculation. This is a static source review of these
fixed schedules, not a proof of the receive API for all malformed input.
The four negative packet controls have the stated limited scope. They are not
network fault injection. Issue/arrival/execution clocks are fixed protocol fields,
not measured transport logs or separate timestamp columns in the trace CSVs.

Reference, command, actual state, and task
The ideal reference is a four-box history. Its analytic derivatives are logged.
The emitted position command is sampled on the 1 kHz simulated clock and held
between samples. Those derivatives must not be presented as derivatives of the
held command or actual robot motion. The final README now states this distinction.
All four configurations for each task have identical command hashes, so changing
the integration step or bias assist does not change the command samples.

Reference tracking uses actual minus reference attachment-site position. Task
error uses actual minus the latest issued goal's attachment-site position. The
goal changes before a delayed request reaches the executor, which correctly
keeps transport delay visible in task error. A final position pass does not erase
transient tracking error, or establish final velocity, acceleration, orientation,
settling, collision safety, or task success for a physical robot.

Frames and forces
All three positions come from site_xpos of attachment_site in the same model
world frame. They omit orientation. The XML locates that site 0.107 m along the
last link's local z axis. Calling it flange position is a declared model
convention; it is not a verified real-robot flange/tool calibration. The revised
README and paper make the world-frame position-only scope explicit.

The ideal assist adds qfrc_bias through qfrc_applied. This extra generalized
force bypasses the position actuator's force clamp. Keeping the original
actuators and their clamps therefore does not certify total joint torque.
The revised README and paper now state this. The assist uses exact model state
and bias terms at each integration step. It is not measured feedforward,
firmware reproduction, or a demonstrated feasible actuator command. The stock
servo's sag is not evidence that a real Franka has the same sag.

Counts and numerical claims
Independent saved-data checks confirm:
- 16 distinct case/servo/step combinations, 2,001 rows each: 32,016 rows total.
- Uniform 1 ms saved clocks from 0 through 2 s, and finite CSV values.
- 201 samples in each final window [1.8,2] s.
- Eight final-position passes, all ideal-assist configurations; eight failures,
  all stock configurations. Recomputed scores agree within 1e-15 m.
- The finer-step assist final maxima are 0, .004522021, .057912170,
  and .112451681 mm for hold, single, reversal, and queued reversal.
- The finer-step queued assist transient tracking maximum is 9.212598124 mm.
- Recomputed little-endian float64 command hashes match the summary.
- The maximum reported flange step-refinement difference is .069950882 mm.
The last item is a summary check, not a new independent refinement calculation.
The no-warning and no-contact statements are supported by saved summary records
and the implementation's checks. I did not independently execute or validate the
dynamics/contact solver. Step refinement is not a rigorous error enclosure.
Sampled jerk estimates change substantially with step size in some cases; no
physical jerk acceptance claim should be inferred from those diagnostics.

Remaining boundary
The current paper fragment stays within its declared scope. Preserve the model,
controller, force, frame, timing, and task distinctions when this is reused.
A real robot comparison still needs a measured execution interface, a compatible
controller, total force/torque limits, payload/frame calibration, and full task
scores. This review does not verify the external hardware documentation or the
Langella paper's missing-proof claim; those depend on the separate source review.
