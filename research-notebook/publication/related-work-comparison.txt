CONCLUSION

The broad ingredients already exist: Lean control foundations, rational SOS
replay, interval matrix-positivity certificates, quantized-controller bounds, and
numerical-witness-to-hybrid-safety pipelines. The strongest defensible prospective
contribution is a small, reusable and evaluated connection from exported exact
polynomial transitions to explicitly held dynamics and scoped sample/intersample
bounds. A claim that Bernstein/LDL is a stronger positivity method is unsupported.

Indeed, the baseline cubic Bernstein witness converts directly to the odd
Markov–Lukács Gram representation already exposed by lean-matrix-sos. The exact
conversion below is useful for interoperability and comparison; it is also a
reason to avoid presenting this certificate class as a new mathematical result.

IMPORTANT QUALIFICATIONS

* LeanForControl's inspected exponential Lyapunov theorem is for an autonomous
  discrete map (its hypothesis removes time dependence). Its broader system API
  does not by itself prove our jitter result. Conversely, its integral trajectory
  definitions are broader than our explicit local polynomial segments. These are
  complementary abstractions, not evidence that one project subsumes the other.
* MatrixSOS's equivalence is a theorem about existence of real certificates.
  It does not, by that statement alone, provide a rational search procedure or
  an executable exporter. Our rational coefficient checker is sufficient and
  may reject a positive polynomial. Neither a failed search nor a rejected
  Bernstein witness proves instability.
* Sparkle's actual source uses x1_next=x1+dt*x2, with fixed dt=1/16, and the
  quantized feedback in x2_next. Our exact held double integrator includes
  h^2*u/2 in position. Comparing the two directly would change the plant map.
  Its chapter reports integer-step transport, but still identifies a Signal-level
  circuit-to-pure-step bridge as simulation-based. Do not flatten its distinct
  evidence layers into either "fully verified hardware" or "only real arithmetic."
* The 2026 zonotope paper uses a fixed sampling period in its displayed model.
  The older KeYmaera line already treats nondeterministic update timing. It would
  be misleading to claim jitter itself as a new formal-verification idea.
* Our source evidence currently proves nominal local segments and their
  sample-index envelopes. A globally stitched real-time solution, uniqueness,
  and physical correspondence are different claims. Newly added saturated-prefix
  work must be cited with its own audit and its one-initial-state quantifiers.

ONE CONCRETE SAME-OBJECT EXPERIMENT

Benchmark object (exactly benchmarks/double-integrator.json):

  A(h) = [[1-h^2, h-(3/2)h^2], [-2h, 1-3h]],
  P = [[5,1],[1,1]], c=1, h in [0,1/2].

  R(h) = (P-A(h)^T P A(h))/h - I, polynomially extended at zero,
       = [[-5h^3-4h^2+6h+3, -(15/2)h^3-h^2+(9/2)h],
          [-(15/2)h^3-h^2+(9/2)h, -(45/4)h^3+6h^2-5h+3]].

The COMMON TARGET is forall h,x,v, 0<=h<=1/2 implies
  [x,v] R(h) [x,v]^T >= 0.
Via the same checked polynomial identity, this gives
  E_P(A(h)z) <= E_P(z)-h*(x^2+v^2).
Use the same P bounds and same held-model bridge for downstream conclusions.
Do not quietly alter P, the controller, c, or the period interval in one arm.

Arm A: existing generated Bernstein/LDL certificate.
  Its residual_psd theorem already checks this object. The manifest records
  6682 bytes and 4.47 seconds for the ENTIRE baseline generated module plus axiom
  output in one local run. That is not yet a fair time for the common target
  alone: the module also proves energy bounds and composed results.

Arm B: leanprover/sos on the scalar residual.
  publication/comparison/UNVERIFIED-SOSComparison.lean gives the exact goal.
  Use its own pinned checkout/toolchain, run sos? once for discovery, freeze the
  returned sos_witness, and then measure replay separately. The file has not
  been elaborated, so no success, failure, or timing result is asserted.
  A second goal uses the existing wide case, with the SAME A and P, c=1/100,
  and h<=33/50. Treat this as a second paired benchmark, not a changed baseline.

Arm C (useful optional checker comparison): MatrixSOS odd Gram certificate.
  Normalize t=2h, let Z(t)=[I;tI] and use the four existing Bernstein coefficients:
    C0=[[3,0],[0,3]], C1=[[4,3/4],[3/4,13/6]],
    C2=[[14/3,17/12],[17/12,11/6]],
    C3=[[35/8,17/16],[17/16,19/32]].
  Then the SAME residual satisfies
    R(t/2) = t Z(t)^T G_left Z(t) + (1-t) Z(t)^T G_right Z(t),
    G_left = [[3C1,-3C1],[-3C1,3C1+C3]],
    G_right = [[C0,-C0],[-C0,C0+3C2]].
  The rational LDL pivots are respectively
    (12,389/64,35/8,47/140), and (3,3,14,943/224), all positive.
  Exact SymPy reconstruction and LDL checks passed. Data and derivation live in
  comparison/UNVERIFIED-matrix-gram.json and comparison/derive_same_object.py.
  A Lean adapter into IccLukacsGramCertificateBoundedOdd d=1,a=0,b=1 is still
  UNVERIFIED. Check its GramIdx basis order and then use the reverse implication
  of posSemidefOn_Icc_iff_lukacsGram_odd. Do not invoke that theorem's forward
  implication using OUR positivity theorem and present the result as independent
  certification. This arm compares replay representations with shared witness
  information; it does not compare independent certificate discovery.

Minimal fair protocol:
  1. Pin source, toolchains, solver version/configuration, CPU/OS, and dependencies.
     Freeze the exact common target and exact input hash before testing.
  2. Record discovery, dependency build, target proof replay, and full-system
     composition separately. Use the same axiom policy for Lean conclusions.
  3. Measure repeated fresh target-file checks after dependencies are built;
     report all runs or median/range, not a selected fastest run. Keep search
     timeout, resource exhaustion, elaboration incompatibility and proof failure
     as distinct outcomes. An incompatible toolchain is not a mathematical loss.
  4. Compare source/witness size, required custom proof code, time, and failures.
     Name the counted representation: source bytes are not kernel proof-term size.
  5. If evaluating sampling conservatism, sweep paired H values with A,P,c fixed
     and publish the complete prespecified grid. The currently different c values
     at H=1/2 and H=33/50 cannot establish a superiority claim.

STRONGEST DEFENSIBLE PROSPECTIVE CONTRIBUTION

"An evaluated Lean interface that accepts exact rational polynomial transition
certificates, checks interval-wide quadratic decay and coercivity, and connects
those certificates to explicitly specified zero-order-held models and composable
sample/intersample bounds, with solver-independent replay and documented semantic
limits."

This is a prospective methods/artifact contribution, not demonstrated novelty.
Its case would rest on useful reuse and measured reduction in manual adaptation
or checking cost, or on a substantive assurance/composition capability established
relative to close prior work. The positive-energy requirement and proved
clipping-inactivity limitation are useful semantic-audit lessons, not by themselves
new control theory. An application selected and reviewed with the user's robotics
expertise is more valuable than multiplying closely related integrator examples.

REJECTION / REDIRECTION CRITERIA

1. If an existing package supplies the same certificate-to-held-system contract
   through a small routine adapter, reject a standalone novelty claim and prefer
   integration, an upstream contribution, or a focused case-study report.
2. If equal-object evaluation finds no useful improvement in reuse, proof effort,
   replay, or assurance scope, do not claim a new certification method merely
   because the implementation is different or written in Lean.
3. If superiority requires changing P, dynamics, margin, period domain, axiom
   policy, or timing boundaries, reject that comparison. Publish comparable
   negative results and diagnose the difference instead.
4. If model bridges, coercivity, nonvacuous assumptions, or clean replay fail,
   withhold the affected system-level claim even if a matrix inequality checks.
5. If broader applicability relies on approximating nonnilpotent dynamics without
   a checked error bound, keep the claim restricted to exact polynomial models.
6. If the only evidence remains a few normalized toy systems and a table of
   successful builds, regard it as a working prototype, not established research
   significance. Seek a substantive application or formalization insight.
