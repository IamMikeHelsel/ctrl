## Problem and known solution
Erdős 815: for k ≥ 3 and n large, must every n-vertex graph with 2n−2 edges whose every proper induced subgraph has minimum degree ≤ 2 ("degree-3-critical") contain C_k? EFGS88 proved cycles of length 3, 4, 5 always exist. Narins–Pokrovskiy–Szabó (Combinatorica 2017) disproved it: arbitrarily large degree-3-critical graphs with no C_23. The even-k version is still open. The disproof is an explicit construction (a cubic-ish tree with leaves arranged to avoid leaf-to-leaf paths of length 20, plus a two-apex augmentation), together with a combinatorial verification of criticality and C_23-freeness.

## What exactly must be proved in Lean
`¬ ∀ k ≥ 3, ∃ N, ∀ n ≥ N, ∀ G : SimpleGraph (Fin n), DegreeThreeCritical G → cycleGraph k ⊑ G`, where `DegreeThreeCritical G := #E = 2|V| − 2 ∧ ∀ s ≠ univ, (G.induce s).minDegree ≤ 2`. This means building an infinite family (parameterized by m), and for each member proving the edge count, the criticality condition for all proper induced subgraphs, and that it has no 23-cycle. Since the family is infinite, a finite `decide` check is not enough.

## Proof plan
This is moot because the proof is already done. If we did it from scratch, we would follow the plby structure: define `avoidingValue` labels, build `treeGraph m` and prove it is a tree, show there are no leaf-to-leaf paths of length 20, show the augmentation has 2n−2 edges and min-degree ≤ 2 on proper induced subgraphs, then rule out C_23 by deleting an apex edge to get a 2-colorable graph and checking the forced routes through the apexes. That's about 2k lines, so L effort.
