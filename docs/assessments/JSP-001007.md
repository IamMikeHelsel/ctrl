## Problem and known solution
Erdős [Er80, p.107] asked: given ε, η > 0, is there a k such that for any primes p_1 < … < p_k < n^{1−ε}, each with a set A_i of (p_i−1)/2 residue classes, at most εn integers m ≤ n avoid every A_i? η is quantified but never used. The large sieve gives "yes" when p_k < n^{1/2}.

Price and GPT-5.4 Pro (erdosproblems.com/1202, April 2026) showed the answer is **no**. Their construction takes many primes in a dyadic interval (m, 2m] with m > √(n log n), lets each A_i be an interval of residues (the upper half), and shows that a positive-density striped set or long arithmetic progression survives every sieve. This leaves at least (1/2 − c)n survivors. The proof is short: a few pages, with prime counting in [m, 2m] as the only analytic input. The JSP catalog lists it as Solved, Lean proof: No, Eligible to claim: No.

## What exactly must be proved in Lean
The negation of the universal statement. It is enough to take ε = 1/10 and, for every k, construct n, k strictly increasing primes below n^{9/10}, and sets A_i of size (p_i−1)/2 that leave more than n/10 survivors in [1, n]. This is exactly what plby's `erdos_1202_counterexample` and `not_erdos_1202` do, in 640 lines.

## Mathlib readiness (exists / missing)
- Exists: `Mathlib/NumberTheory/Bertrand.lean`, `PrimeCounting.lean`, `Chebyshev.lean` (Chebyshev-type bounds), ZMod and Finset counting.
- Missing / needed: a lower bound on the number of primes in [M, 2M] that grows like M/log M with an explicit constant, used to get k primes clustered in one dyadic interval. plby imports `BoundedGaps.PrimeNumberTheorem.Analytic.PrimeCounting` for this. An elementary alternative is Chebyshev lower bounds for π(2M) − π(M), which may need a weaker constant but still works for ε = 1/10. Elementary routes are already submitted (PR 2284, szchan's repo in PR 5072).

## Proof plan
(Moot because of priority.) Choose M large and Q many primes in (M, 2M] with k ≤ Q. Let A_i be the upper-half residues {a : (p+1)/2 ≤ a.val}. The survivors include aligned blocks x with x mod p ≤ (p−1)/2 for every p in the cluster, which follows from common-remainder arguments when all p are close to each other. Count the blocks to get more than n/10 survivors, then check p < n^{9/10} via p^10 < n^9. No finite computation is needed, so neither `decide` nor `native_decide` is required.
